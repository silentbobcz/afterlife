Redscript error analysis

When the game cannot compile redscript, no script mod runs, and the user only sees some other mod misbehave. The game writes the reason to r6\logs\redscript_rCURRENT.log. AFTERLIFE reads that log, names the mods behind it and offers to switch them off through the normal switch-off. It never deletes anything; the user applies the changes as usual.

At app start the same banner appears when the log is newer than the last one AFTERLIFE looked at (the game was started outside AFTERLIFE); only the first sentence changes: “The game could not compile redscript the last time it ran …”. Dismiss hides it until the game writes a new log. Orange, not magenta: the game still starts, it is not a blocking error like an unfinished change.

Where the manual button lives

RECOMMENDED · a new first line in the LIST & ORDER menu under the mod list
ANALYZE REDSCRIPT ERROR NEW
Script mods not working? Read the game's script log and find the mod behind it
EXPORT LIST
Active mods with versions, for a bug report or a forum post
EXPORT ORDER
Save the load order of this profile to a text file
IMPORT ORDER
Load an order from a file; you see what changes first
RESET ORDER
Back to the game's alphabetical order; nothing changes in the game before you apply
Everything is applied · 212 mods on
REFRESHCHECK UPDATESLIST & ORDER ▴

Why here: it is a now-and-then tool, like EXPORT LIST (also for troubleshooting), and it adds no button to the row. Its sentence says when to use it, which a button alone could not. The menu name could then become MORE ▾, which the menu preview already left open.

Alternative: a quiet link “Script mods not working? Analyze” under JACK IN in the left panel, next to the launch hint. Always visible and close to where the problem starts, but it adds a line to the calm launch area for something most users never need.
